# 1. 模組 1：應用外殼與可觀測性（認證 + 聊天 UI + Gemini 串流 + LangSmith）

**複雜度指標：** ⚠️ **中等** - 涵蓋資料庫 Schema、FastAPI 後端、React 前端與第三方 API 整合，按步驟依序執行並逐步驗證即可穩定完成。

---

## 目標概述
建立 Agentic RAG 系統的基礎應用外殼（App Shell），包含：
1. **Supabase 資料庫與認證（Auth + RLS）**：用戶登入/註冊，以及具備行級安全性（Row-Level Security）的 `threads`（對話串）與 `messages`（訊息）資料表。
2. **FastAPI 後端（Python `venv`）**：使用 `openai` SDK 連接 **Google AI Studio (Gemini)** 的 OpenAI 兼容端點，並透過 `langsmith.wrappers.wrap_openai` 自動追蹤每次 LLM 調用，透過 SSE（Server-Sent Events）串流回傳給前端。
3. **React + Vite + Tailwind + shadcn/ui 風格前端**：提供清爽現代的登入/註冊頁、左側對話線程管理列、右側支援 Markdown 與即時打字機串流效果的聊天視窗，以及頂部「聊天 / 文件導入（模組 2 啟用）」切換導覽。

## 任務清單與驗證測試

### 任務 1：環境變數配置與資料庫 Schema 準備
- **實作內容**：
  1. 在專案根目錄建立 `.env.example` 與 `.env` 設定檔範本，統一管理：
     - `SUPABASE_URL`、`SUPABASE_ANON_KEY`、`SUPABASE_SERVICE_ROLE_KEY`（選填，或後端透過用戶 JWT 操作 RLS）
     - `GEMINI_API_KEY`、`LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/`、`LLM_MODEL=gemini-2.5-flash`
     - `LANGSMITH_TRACING=true`、`LANGSMITH_API_KEY`、`LANGSMITH_PROJECT=agentic-rag`
  2. 建立 `supabase/migrations/001_module1_schema.sql`，定義：
     - `threads` 表：`id (uuid, PK)`, `user_id (uuid, FK auth.users)`, `title (text)`, `created_at (timestamptz)`, `updated_at (timestamptz)`
     - `messages` 表：`id (uuid, PK)`, `thread_id (uuid, FK threads on delete cascade)`, `user_id (uuid, FK auth.users)`, `role (text: 'user' | 'assistant' | 'system')`, `content (text)`, `created_at (timestamptz)`
     - 啟用 `threads` 與 `messages` 的 RLS（Row-Level Security），確保用戶只能查詢、新增、修改、刪除 `auth.uid() = user_id` 的資料。
- **驗證測試**：
  - 執行環境變數檢查腳本確認 `.env` 必填欄位皆已正確填入且無格式錯誤。
  - 在 Supabase SQL Editor 執行 `001_module1_schema.sql` 後，透過後端測試腳本確認 `threads` 與 `messages` 表存在且 RLS 正常運作。

---

### 任務 2：Python FastAPI 後端與 Gemini + LangSmith 串流整合
- **實作內容**：
  1. 在 `backend/` 目錄下建立 Python `venv` 虛擬環境並安裝依賴（`fastapi`, `uvicorn`, `supabase`, `openai`, `langsmith`, `pydantic`, `pydantic-settings`, `python-dotenv`, `sse-starlette`）。
  2. 建立核心模組：
     - `backend/app/config.py`：讀取環境變數。
     - `backend/app/auth.py`：驗證前端傳來的 Supabase Bearer Token（JWT），取得當前 `user_id` 與帶有使用者權限的 Supabase Client。
     - `backend/app/llm.py`：初始化 `AsyncOpenAI(api_key=GEMINI_API_KEY, base_url=LLM_BASE_URL)`，並使用 `langsmith.wrappers.wrap_openai` 包裝以自動上報 LangSmith 追蹤紀錄。
     - `backend/app/routers/threads.py`：提供 `GET /api/threads`、`POST /api/threads`、`DELETE /api/threads/{thread_id}`、`GET /api/threads/{thread_id}/messages`。
     - `backend/app/routers/chat.py`：提供 `POST /api/chat/stream`（SSE 串流端點），接收使用者訊息 → 存入 `messages` 表 → 讀取該 `thread_id` 歷史訊息 → 呼叫 Gemini Chat Completions Stream → 即時透過 SSE 推送文字片段（delta） → 完成後將 AI 完整回覆存入 `messages` 表，若為第一則訊息則自動更新對話標題。
     - `backend/app/main.py`：整合 CORS、路由與 `GET /api/health` 健康檢查端點。
- **驗證測試**：
  - 啟動 FastAPI 伺服器，呼叫 `curl http://localhost:8000/api/health` 確認回傳 `{"status": "ok"}`。
  - 執行後端連線測試腳本，確認 Gemini API 與 LangSmith 追蹤可正常跑通並回傳串流回應。

### 任務 3：React + Vite + Tailwind + shadcn/ui 前端構建
- **實作內容**：
  1. 在 `frontend/` 建立 React + TypeScript + Vite 專案，配置 Tailwind CSS、Lucide 圖示與 shadcn/ui 風格元件。
  2. 建立核心頁面與元件：
     - `src/lib/supabase.ts`：初始化前端 Supabase Client。
     - `src/components/AuthPage.tsx`：支援 Email + 密碼登入與註冊的表單介面，附帶清楚的錯誤提示。
     - `src/components/Layout.tsx`：頂部導覽列（切換「💬 聊天」與「📄 文件導入（模組 2 解鎖）」視圖、顯示當前登入信箱與登出按鈕）。
     - `src/components/ChatView.tsx`：
       - 左側欄：新增對話按鈕、歷史對話線程列表（支援切換與刪除）。
       - 右側主視區：訊息列表（支援 Markdown 渲染）、底部輸入框（支援 Enter 發送、Shift+Enter 換行）、SSE 即時串流接收與載入狀態指示。
- **驗證測試**：
  - 執行 `npm run build` 確認 TypeScript 型別與打包零錯誤。
  - 啟動前端開發伺服器（`http://localhost:5173`），確認畫面正常渲染。
