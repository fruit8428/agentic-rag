# 模組 5 實施計劃：多格式文件支持（PDF / DOCX / HTML / Markdown / CSV / TXT）與級聯刪除

## 1. 模組目標
在真實企業與扶輪社團應用中，知識庫不僅只有 PDF，還常包含 **Word 文件（`.docx`）**、**網頁公告（`.html`）**、**結構化名冊（`.csv`）** 與 **Markdown 筆記（`.md`）**。
此外，當用戶刪除一份錯誤或過期的文件時，系統必須確保 **「級聯刪除（Cascade Delete）」** 徹底清除：
1. Supabase Storage 雲端儲存桶中的原始檔案
2. `documents` 主表中的文件紀錄
3. `document_chunks` 向量表中的所有 `pgvector` 嵌入分塊（確保零孤兒向量殘留，不會在聊天檢索中出現「幽靈舊資料」）

---

## 2. 核心架構設計

### A. 統一多格式文件轉 Markdown 解析器（`backend/app/services/document_parser.py`）
採用 Docling 核心設計理念——**「將所有異質格式統一轉換為結構化 Markdown（保留標題層級與表格結構）」**，再交由分塊器處理：
1. **PDF (`.pdf`)**：透過 `pypdf` 逐頁解析 + `unicodedata.normalize("NFKC")` 康熙字典部首正規化 + 頁碼標記。
2. **Word (`.docx`)**：透過 `python-docx` 依文件原始段落與表格順序讀取，將標題（`Heading 1~3`）轉為 `# / ## / ###`，並將 Word 表格（`<w:tbl>`）自動轉換為 GitHub Flavored Markdown 表格（`| 欄位1 | 欄位2 |`），確保表格行列關係不流失。
3. **HTML (`.html`, `.htm`)**：透過 `BeautifulSoup4` 移除 `<script>`、`<style>`、`<nav>` 等雜訊標籤，將 `<h1>~<h6>`、`<table>`、`<ul>/<ol>` 轉換為乾淨的 Markdown 結構。
4. **CSV (`.csv`)**：自動偵測 UTF-8 / Big5 編碼並轉換為 Markdown 表格。
5. **Markdown / TXT (`.md`, `.txt`)**：支援 UTF-8 / UTF-8-SIG / CP950 (Big5) 自動解碼。
6. **Docling 引擎自動相容**：若環境中安裝有 `docling`，自動支援呼叫 `DocumentConverter`；預設使用輕量極速的原生轉換引擎，確保 macOS 0 延遲秒級解析。

### B. 級聯刪除與零殘留驗證（`DELETE /api/documents/{document_id}`）
- 刪除前先統計該文件擁有的向量分塊數（`deleted_chunks_count`）。
- 同步從 Supabase Storage 移除原始檔案。
- 刪除 `documents` 主表紀錄並觸發 PostgreSQL `ON DELETE CASCADE` 自動清除所有 `document_chunks`。
- 二次驗證 `document_chunks` 中該 `document_id` 的剩餘筆數為 `0`，回傳完整的 `CascadeDeleteReport` 顯示於前端。

### C. 前端介面升級（`IngestView.tsx` & `App.tsx`）
- 上傳區支援 `.pdf, .docx, .html, .htm, .md, .csv, .txt`。
- 每張文件卡片新增 **模組 5 格式與解析統計徽章**（顯示檔案格式、解析引擎、頁數／章節數、偵測到的表格數量）。
- 新增 **「🧪 模組 5 多格式與級聯刪除實驗室」**，支援一鍵生成並導入帶有複雜表格的 `.html` 網頁公告與 `.csv` 結構化名單，以及刪除時的「級聯刪除報告橫幅」。
