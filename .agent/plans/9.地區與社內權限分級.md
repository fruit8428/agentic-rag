## 需求（使用者 2026-11-03 確認）
1. 系統給扶輪社 3523 地區使用，資料分兩級：
   - **地區級**：所有 3523 地區社友都能看。
   - **社內級**：只有該社社友能看，不對外。
2. 使用者會提供地區內所有社的社名；之後要能新增、刪除社。
3. 每個社有自己的「社內密碼」，由社自己設定。知道社內密碼的人就能看該社全部資料＋地區資料。
4. 一個人只屬於一個社。
5. 能進入社內的人都可以上傳自己社的資料（通常由執秘上傳）。
6. 現有兩份文件（頒獎名單、保齡球 PDF）都是地區級。

## 設計決策（未明說的部分，採用以下預設，已向使用者說明）
| 項目 | 決策 | 理由 |
|---|---|---|
| 地區管理員 | `profiles.role = 'admin'`，初始為 fruit8428@gmail.com | 需要有人管理社的清單與地區級文件 |
| 誰能上傳地區級文件 | 只有管理員 | 地區級所有人可見，應受控 |
| 社內密碼初始值 | 管理員建社時設定；社友之後可在「社設定」用舊密碼改新密碼；管理員可直接重設 | 「自己的社自己設定」＋管理員能救援忘記密碼 |
| 沒加入社的帳號 | 看不到任何文件、不能聊天（API 回 403），前端只顯示「加入社」頁 | 註冊目前是開放的，用「必須先用社內密碼加入」來擋外人 |
| 換社 | 社友自己不能換；管理員可重新指派 | 一人一社，避免用一組密碼到處看 |
| 刪除社 | 社內還有社友或文件時拒絕刪除，顯示清楚錯誤 | 防誤刪 |
| 刪除文件 | 上傳者本人或管理員 | 延續現有防誤刪規則 |
| 密碼儲存 | bcrypt 雜湊，絕不存明文 | 基本安全 |

## 權限規則（一句話）
> 使用者 U 能看到文件 D ⇔ `D.scope = 'district'` 或 `D.club_id = U 所屬社`。

此規則在**兩層**同時強制：
1. **資料庫 RLS**（第一道防線，即使後端寫錯也擋得住）。
2. **後端 `visibility.py` 共用函數**（因為檢索走管理員連線繞過 RLS，必須在程式裡套同一條規則）。

## 資料模型
```
clubs            id, name(唯一), password_hash, created_at
profiles         user_id(PK→auth.users), club_id(→clubs, 可空), role('member'|'admin'), joined_at
documents        + scope('district'|'club'), + club_id(→clubs, 可空；scope='club' 時必填)
document_chunks  不加欄位，RLS 透過 join documents 判斷
```

## 執行順序與整體驗證
1. 9a → 9b → 9c 依序完成，每個子計劃內有各自的驗證測試。
2. **端到端驗證（全部完成後）**：
   - 建兩個測試帳號 A（甲社）、B（乙社），各上傳一份社內文件。

   - 沒加入社的新帳號呼叫 `/api/chat/stream` → 403。
   - 管理員新增社、刪除空社成功；刪除有社友的社被拒絕。
