# 模組 4 實施計劃：元數據提取（Metadata Extraction — Pydantic 結構化提取與元數據過濾檢索）

## 1. 模組目標與學習重點

當知識庫裡的文件越來越多（例如同時有《2025 年頒獎名單》、《2026 年頒獎名單》、《社務章程》、《Claude 插件指南》），僅靠純文字與向量搜尋容易把不同年份或不同類別的文件混在一起。

**模組 4（元數據提取 Metadata Extraction）的解決方案：**
1. **LLM + Pydantic 結構化元數據提取**：
   在文件導入（Ingestion）時，取文件前段與後段代表性內容，交由 Google Gemini 並透過 **Pydantic (`DocumentMetadataSchema`)** 強制驗證與解析出結構化 JSON 元數據：
   - `document_title`：文件正式標題
   - `category`：文件類型（如：`頒獎與表揚名單`、`會議與活動通知`、`技術與操作指南`、`規章與辦法` 等）
   - `event_or_year`：所屬年份或活動日期（如：`2026年3月29日`）
   - `summary`：50～100 字的繁體中文核心摘要
   - `keywords`：5～8 個關鍵標籤（Tags）
2. **元數據增強與過濾檢索（Metadata-Filtered Retrieval）**：
   - 將提取出的元數據寫入文件與分塊的 `metadata` JSONB 中。
   - 升級 Agent 的 `search_knowledge_base` 工具參數，支援 `category_filter`（依文件類別過濾）與 `filename_filter`（依特定文件過濾），同時在聊天室輸入框上方提供直覺的「📂 知識庫過濾器（全部文件／指定特定文件或類別）」。

## 2. 系統架構與檔案變更清單

| 檔案路徑 | 變更類型 | 說明 |
| :--- | :--- | :--- |
| `supabase/migrations/004_module4_metadata_schema.sql` | 新增 | 選配增強 SQL：為 `document_chunks.metadata` 建立 GIN JSONB 索引加速元數據過濾（後端同時直接支援 JSONB 讀取與過濾，免手動跑 SQL 即可運作） |
| `backend/app/services/metadata_extractor.py` | 新增 | 定義 Pydantic `DocumentMetadataSchema`，呼叫 Gemini 提取結構化元數據並寫入 Supabase |
| `backend/app/services/ingestion.py` | 修改 | 在文件導入完成分塊後，自動呼叫 `extract_document_metadata` 寫入結構化元數據 |
| `backend/app/routers/documents.py` | 修改 | 回傳每份文件的 `extracted_metadata`，並新增 `POST /api/documents/{id}/extract-metadata` 手動觸發端點 |
| `backend/app/routers/chat.py` | 修改 | 擴充 `search_knowledge_base` 工具參數（支援 `category_filter`、`filename_filter`）與前端指定文件過濾 |
| `frontend/src/components/IngestView.tsx` | 修改 | 在每份文件卡片展示 AI 提取的類別標籤、年份、核心摘要與關鍵字 Pills，並提供「✨ 重新提取元數據」按鈕 |
| `frontend/src/components/ChatView.tsx` | 修改 | 在聊天輸入框上方新增「📂 檢索範圍過濾器」，可一鍵限定 AI 只在特定文件或類別中檢索 |
| `frontend/src/App.tsx` | 修改 | 頂部導覽列進度徽章更新為「模組 4：元數據提取與過濾檢索」 |
| `PROGRESS.md` | 修改 | 追蹤並勾選模組 4 各項實施步驟 |

## 3. 驗證步驟

1. 自動對現有的《2026地區年會三全四全頒獎名單0421.pdf》執行 Gemini + Pydantic 元數據提取，驗證成功產生類別、年份、摘要與關鍵字標籤。
2. 在前端「📄 文件導入」頁面檢視結構化元數據卡片。
3. 在前端「💬 AI 聊天」頁面測試元數據過濾檢索。
