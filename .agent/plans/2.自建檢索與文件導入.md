# 2. 模組 2：自建檢索 + 文件導入（Supabase pgvector + Gemini Embedding + Agentic 工具調用）

**複雜度指標：** ⚠️ **中等** - 包含 pgvector 向量資料表與搜尋函數、檔案上傳與分塊嵌入管道、Supabase Realtime 狀態同步，以及 Agent 工具調用（Tool Calling）串流整合。

---

## 目標概述
在模組 1 的基礎上，打造完整的自建 RAG（檢索增強生成）管道與文件管理介面：
1. **Supabase `pgvector` 向量資料庫與 RLS**：建立 `documents`（文件表）與 `document_chunks`（768 維度向量分塊表），並建立 `match_document_chunks` 向量相似度檢索函數。
2. **文件導入與向量化管道（Ingestion Pipeline）**：支援手動拖放上傳文件（PDF / Markdown / TXT）→ 存入 Supabase Storage → 文本提取與重疊分塊（Chunking with Overlap）→ 呼叫 Google AI Studio `gemini-embedding-001`（768 維度）生成嵌入向量 → 存入 `pgvector`。
3. **Supabase Realtime 即時狀態更新**：前端「文件導入」頁面透過 Supabase Realtime 訂閱 `documents` 表變更，即時顯示「處理中 → 已完成（含分塊數量）」。
4. **Agentic RAG 工具調用（Tool Calling）**：賦予 Gemini `search_knowledge_base` 檢索工具，讓 AI 根據使用者問題自主決定是否檢索知識庫，並在聊天介面即時展示「檢索工具調用過程與參考來源段落」。

---

## 任務清單與驗證測試

### 任務 1：建立 Supabase `pgvector` 資料表、RLS 與向量檢索函數
- **實作內容**：
  1. 編寫 `supabase/migrations/002_module2_rag_schema.sql`：
     - 啟用 `vector` 擴充套件（`create extension if not exists vector;`）。
     - 建立 `documents` 表與 RLS 策略，並將其加入 `supabase_realtime` publication。
     - 建立 `document_chunks` 表（含 `embedding vector(768)` 欄位與 HNSW 向量索引）與 RLS 策略。
     - 建立 `match_document_chunks` Postgres RPC 函數，依餘弦相似度（Cosine Similarity）與 `match_threshold` 回傳最相關的文件片段。
- **驗證測試**：
  - 在 Supabase SQL Editor 執行 `002_module2_rag_schema.sql`，透過後端腳本驗證 `documents` 與 `document_chunks` 表可正常讀寫且 `match_document_chunks` RPC 呼叫成功。

---

### 任務 2：後端文件導入 API（解析、分塊、Gemini Embedding）
- **實作內容**：
  1. 在 `backend/` 安裝 `pypdf` 與 `python-multipart`（支援表單檔案上傳與 PDF 解析）。
  2. 建立 `backend/app/services/ingestion.py`：
     - 提取 PDF / TXT / MD 文本內容。
     - 實作智慧分塊器（預設每塊約 800 字元、重疊 150 字元，優先在段落或句號處切分）。
     - 呼叫 `llm_client.embeddings.create(model="gemini-embedding-001", dimensions=768)` 批次轉為向量。
  3. 建立 `backend/app/routers/documents.py`：
     - `GET /api/documents`：取得當前用戶的文件列表。
     - `POST /api/documents/upload`：上傳檔案至 Supabase Storage `documents` 儲存桶，建立 `processing` 紀錄並啟動背景分塊與向量化任務。
     - `DELETE /api/documents/{document_id}`：刪除文件與關聯分塊。
- **驗證測試**：
  - 使用本地測試 PDF 檔案測試分塊與 `gemini-embedding-001` 向量生成，確認產出 768 維向量並成功寫入資料庫。

---

### 任務 3：Agentic RAG 檢索工具與聊天串流升級
- **實作內容**：
  1. 在 `backend/app/routers/chat.py` 定義 OpenAI 兼容格式的 Tool：`search_knowledge_base(query: str)`。
  2. 當使用者發送訊息時：
     - 先讓 Gemini 判斷是否需要呼叫 `search_knowledge_base` 工具。
     - 若觸發工具調用，透過 SSE 推送 `tool_start` 與 `tool_end`（附帶檢索到的文件名、片段內容與相似度分數），再將檢索結果交由 Gemini 串流生成最終回答。
- **驗證測試**：
  - 發送與上傳 PDF 相關的問題，確認後端觸發 `search_knowledge_base` 工具、撈出正確分塊並由 LangSmith 完整記錄 Trace。

---

### 任務 4：前端「文件導入」介面與聊天室檢索來源展示
- **實作內容**：

     - 啟用頂部導覽列的「📄 文件導入」分頁。
     - 在聊天訊息中渲染「🔍 已檢索知識庫（點擊展開查看參考段落與相似度）」卡片。
- **驗證測試**：
  - 執行 `npm run build` 確認前端編譯無誤，並在瀏覽器實測上傳《Claude Cowork 插件強大功能》PDF 後在聊天室提問驗證。
